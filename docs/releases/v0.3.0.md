# ShouldaUsedThat v0.3.0

This release makes the project easier to understand before asking readers to learn its evidence
machinery. The fastest paths are now explicit: browse the catalog, run a no-authentication check,
or install the verified wheel.

## What is new

- Browse 222 reviewed records through 12 need-based collections, with the decision context kept on
  every entry.
- Follow a short, public-fixture walkthrough from `checked` through a revisitable decision without
  a GitHub login.
- Read outcome-oriented CLI help that explains the human question behind each command.
- See the repository's own OSS choices and its catalog-to-GitHub execution as worked examples.
- Use clearer catalog pages that place need, rationale, status meaning, and reconsideration before
  audit detail.

The rewrite was tested with context-free First Reader reviews and ZeroSlop's local formal-prose
checks. These are editorial aids only: repository evidence still owns every fact and qualifier,
and the runtime remains deterministic and AI-free.

## Install

Python 3.12–3.14 and `uv` are required:

```console
uv tool install https://github.com/pradeeptathineni/shoulda-used-that/releases/download/v0.3.0/shoulda_used_that-0.3.0-py3-none-any.whl
shoulda --help
```

PyPI remains intentionally unused.

## Safety boundary

The mutation boundary is unchanged. Read, reason, record, inspect, curate, export, and project
commands cannot write to a target or mutate GitHub. `apply` accepts only an approved, unexpired,
exact-fingerprint `github-curation` plan for the exact account in an interactive terminal. Its
possible changes are additive: create a public List, star a public repository, or add membership
while preserving current memberships. It cannot unstar, remove membership, delete or rename a
List, change privacy, run in CI, or edit a target repository. `verify` independently reads the
claimed postconditions back.

# ShouldaUsedThat v0.2.0

This release turns the local decision tool into an evidence-backed OSS curation coordinator while
keeping GitHub, standards-based SBOMs, and static files authoritative at their natural boundaries.

## Highlights

- Inspect an explicit GitHub project, bounded local root, or supplied SPDX/CycloneDX SBOM without
  writing to the target.
- Compile versioned curation profiles into deterministic snapshots that preserve dispositions,
  collection meaning, exclusions, freshness, provenance, and reconsideration triggers.
- Read GitHub Stars and Lists, then seal the exact additive account, baseline, operations, caps,
  expiry, and fingerprint before any mutation is possible.
- Apply only approved public-List creation, public-repository starring, and membership union from
  an interactive terminal; independently read back every postcondition with `verify`.
- Browse the project's own allowlisted OSS catalog as portable Markdown/JSON or at the
  [GitHub Pages site](https://pradeeptathineni.github.io/shoulda-used-that/).
- Run deterministic read-only catalog upkeep locally or on the least-privilege scheduled workflow.

## Safety boundary

GitHub stars remain bookmarks, Lists remain a deliberately lossy public projection, and canonical
ShouldaUsedThat receipts remain the evidence ledger. Apply fails closed for an account mismatch,
missing capability, state drift, expired plan, exceeded cap, non-TTY input, CI, partial readback, or
unknown plan kind. There is no unstar, membership-removal, List deletion/rename/privacy change,
private-repository exposure, unattended apply, target remediation, runtime model, telemetry,
hosted backend, or database path.

No live personal Star or List mutation was needed to validate this release. The first such change
still requires the maintainer to approve the exact newly sealed plan after reviewing its account,
fingerprint, ordered operations, and caps.

## Distribution and provenance

The GitHub release contains the source archive, wheel, runtime-accurate CycloneDX SBOM,
`SHA256SUMS`, and GitHub artifact attestations. The release workflow builds the wheel from the
annotated tag, installs it into a clean environment, and verifies the CLI before publication.
PyPI remains intentionally untouched; GitHub Releases is the only package distribution surface.
